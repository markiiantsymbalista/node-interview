# Кандидатське завдання: Code Review Node.js сервісу

## Контекст

У цьому завданні вам надано невеликий Node.js сервіс, який обробляє запити на доставку документів.

Базовий бізнес-флоу такий:

1. Система створює delivery request.
2. Зовнішній клієнт згодом надсилає feedback про результат доставки.
3. Якщо доставка була успішною **в межах SLA 20 секунд**, система має:
   - списати кошти з користувача;
   - надіслати нотифікацію користувачу.
4. Якщо feedback не надійшов вчасно або доставка неуспішна, списання не повинно відбутись.

Для асинхронної обробки використовується message broker, а для збереження стану — PostgreSQL.

---

## Ваше завдання

Вам потрібно провести **code review pull request**, ніби це реальний production change у команді.

---

## Що ми очікуємо від вашого review

Під час інтерв’ю ми попросимо вас пройтись по PR і проговорити:

### 1. Blockers
Що в цьому PR ви б вважали критичними проблемами, які не дозволяють мерджити зміни.

### 2. Strong suggestions
Що варто суттєво покращити, навіть якщо це не є абсолютним blocker.

### 3. Nice to have
Менші покращення, які не критичні, але зробили б рішення кращим.

### 4. Questions / assumptions
Які питання ви б поставили автору PR або product / engineering контексту, щоб краще оцінити рішення.

### 5. Merge decision
Ваш фінальний висновок:
- approve
- request changes

і коротке пояснення чому.

---

## Що НЕ є головною метою

Це завдання не про:
- naming nitpicks;
- formatting;
- дрібні stylistic preference;
- “переписати все по-іншому”.

Нас більше цікавить ваше інженерне мислення в production-контексті:
- як ви бачите ризики;
- як пріоритизуєте проблеми;
- як мислите про reliability та consistency.

---

## Формат обговорення на інтерв’ю

Під час розмови ви можете рухатися у будь-якому зручному для вас порядку, але зазвичай найкращий підхід:

1. коротко сформулювати, що робить система;
2. назвати найризикованіші місця;
3. пройтися по blockers;
4. дати suggestions;
5. поставити clarifying questions;
6. дати фінальний merge decision.
